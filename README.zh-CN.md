# Crafter（合成器）插件

以 **投掷器（dropper，方块 158）为原型** 实现的《我的世界》合成器（Crafter）机制，
运行于 Cuberite。放置后可配合漏斗装填、用红石信号触发自动合成，把产物从正面弹出，
并支持锁定槽位。

> **为什么用投掷器做原型？** 投掷器免费提供：红石激活、方块朝向、随世界存档的 3×3
> 物品格、漏斗互操作和原生容器弹出——正好是合成器需要的全部基础。

## 功能

- **3×3 合成格**：合成器物理上是投掷器方块，其原生 3×3 cItemGrid 直接作为合成格，
  且随世界存档持久化。
- **GUI 即原生投掷器窗口**：不弹自定义 GUI，右键直接打开投掷器自带的 3×3 窗口
  （槽位即合成格，与背包完全实时同步，天然规避本服务 cLuaWindow 的崩溃/不同步缺陷）。
- **红石触发合成**：收到红石信号上升沿（拉杆/按钮/红石块/火把等供电）后，延迟
  4 游戏刻（2 红石刻），自动匹配配方、消耗材料并把产物从正面弹出。
- **可禁用槽位**：禁用的槽不参与配方匹配、不参与漏斗装填，其中物品保留。
- **GUI 槽位锁定**：锁定槽也不能透过窗口往里塞物品——看门狗约 0.25 秒内回滚玩家的
  放入并把这些物品从合成器正面弹出（容器优先，否则掉落物）；取出仍然允许，与原版
  锁定槽语义一致。机制与局限详见 [docs/gui-slot-locking.md](docs/gui-slot-locking.md)。
- **漏斗规则**：漏斗只往“第一个空的非禁用槽”（从左到右、从上到下）装填；没有
  空槽时合并到同类的最小堆叠；全部不可装填则拒收。
- **输出路由**：产物优先存入正前方容器（箱子、漏斗等），否则生成为掉落物。
- **合成器物品**：可通过 `/crafter` 获得，或在普通工作台按原版 3×3 配方制作；
  放置时自动注册为合成器；挖掉时掉落合成器物品 + 内部物品。
- **合成器合成合成器**：把合成器自己的配方注入插件配方库，往合成器 3×3 格里按图
  摆放后触发红石，即可合成并弹出新的合成器。
- **持久化**：禁用槽位与自定义名称保存在 `crafters.dat`，重启后恢复。

## 安装

1. 把 `Crafter/` 文件夹复制到服务器 `Plugins/` 目录。
2. 重启服务器（或控制台执行 `reload`）。
3. 按下面的权限说明给你的组/职级授权。

## 命令与权限

| 命令 | 权限 | 适用 | 说明 |
|---|---|---|---|
| `/crafter [名称]` | `crafter.get` | 所有玩家 | 获得合成器物品（可自定义显示名） |
| `/crafter help` | `crafter.admin` | 管理员 | 显示全部子命令 |
| `/crafter list` | `crafter.admin` | 管理员 | 列出已注册的合成器 |
| `/crafter info <x> <y> <z>` | `crafter.admin` | 管理员 | 显示方块、名称、禁用槽、格子内容 |
| `/crafter place <x> <y> <z> [名称]` | `crafter.admin` | 管理员 | 在指定坐标生成并注册合成器 |
| `/crafter give <玩家> [名称]` | `crafter.admin` | 管理员 | 给其他玩家一个合成器物品 |
| `/crafter set` / `setall` | `crafter.admin` | 管理员 | 设置一格或全部 9 格（`物品 0` 清空） |
| `/crafter toggle <x> <y> <z> <槽>` | `crafter.admin` | 管理员 | 切换槽位禁用状态 |
| `/crafter pulse` / `craft` | `crafter.admin` | 管理员 | 模拟红石脉冲 / 立即执行一次合成周期 |
| `/crafter del <x> <y> <z>` | `crafter.admin` | 管理员 | 注销一个合成器 |
| `/crafter save` / `reloaddb` | `crafter.admin` | 管理员 | 保存注册表 / 重载配方库 |

所有管理子命令同样提供了服务端控制台命令 `crafter`（控制台无需权限）。
完整命令参考与实例见 [TESTING.md](TESTING.md)。

**权限设置：**

- `crafter.get` —— 允许玩家获取合成器物品。建议授予默认组/职级（所有需要合成
  合成器的玩家）。
- `crafter.admin` —— 在游戏内使用全部管理子命令。只建议授予管理员/操作员
  （拥有 `*` 通配权限的职级自动获得）。

## 配置（settings.ini）

```ini
[Crafter]
CraftDelayTicks=4      ; 红石触发到合成执行的延迟（游戏刻）
EnableSounds=true      ; 合成音效
EnableParticles=true   ; 合成粒子
Debug=false            ; 调试日志
```

## 文件结构

| 文件 | 作用 |
|---|---|
| `main.lua` | 初始化、钩子注册、`/crafter` 命令分发 |
| `crafter_core.lua` | 核心机制：注册表、红石→合成→弹出、漏斗规则、持久化、合成器物品 |
| `crafter_recipes.lua` | 纯 Lua 的 crafting.txt/items.ini 解析器 + 3×3 配方匹配器 |
| `crafter_dbg.lua` | 管理接口（控制台 + 游戏内 `crafter.admin`） |
| `settings.ini.example` | 配置样例 |

合成器物理上是投掷器方块实体，由插件侧注册表标记。自定义名称和禁用槽位是插件
唯一需要额外记录的状态，其余（格子、朝向、红石、弹出）全部由投掷器原生提供。

## 本 build 的兼容性说明

- **方块 ID**：本 build 映射 dropper=158 / dispenser=23（与官方 API 文档不同），
  插件只通过 `E_BLOCK_DROPPER` 引用 158。
- **不使用自定义 GUI**：本服务的 cLuaWindow 点击/拖拽路径（`OnLeftPaintEnd`）
  会崩溃服务端，因此合成器直接使用投掷器原生 3×3 窗口。
- **红石只对真实客户端放置的投掷器生效**：`SetBlock` 创建的 dropper 不触发
  HOOK_DROPSPENSE 也不会被标记存档；合成器必须用合成器物品放置。
- **已绕过的绑定缺陷**：`AddItems` 返回“加入数量”且原地改写 cItems；供电时
  投掷器 meta 置第 4 位（0x8），朝向读取已做 `% 8` 屏蔽；`GetValueSetB` 对
  `"true"` 返回 false，布尔配置手动解析；部分路径下箱子方块实体没有
  `GetContents`，输出已做 `DoWithChestAt` 回退。
- **GUI 锁定是“回滚式”而非“拦截式”**：本 build 没有窗口点击钩子、也没有逐槽锁定
  API，插件只能事后检测并回滚对锁定槽的放入（打开的窗口会自动同步）；无法显示
  原版 1.21 的灰色“锁定”覆盖层（那是客户端渲染特性）。
